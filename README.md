# santa-game: Evil Santa Co-op (prototype)

Online co-op party game: 2 to 4 elves carry wobbly presents to the sleigh while Evil Santa steals and smashes them.
Unity 6 LTS, URP, Netcode for GameObjects with Unity Lobby + Relay (Steam invites layered on for PC), gamepad first, sized to run on Switch-class hardware.

This repo is the 8-week graybox prototype. **Week 1 goal: one elf that feels good to move around alone.**

## First-time setup (about 15 minutes)

The repo holds only our own files; Unity generates the rest. You need the latest **Unity 6 LTS** in Unity Hub and **Git LFS** (`git lfs install`, once per machine).

1. In Unity Hub, create a new project from the **Universal 3D** template, called `EvilSantaCoop`. Close Unity.
2. Turn that folder into this repo, in a terminal inside the project folder:
   ```sh
   git init
   git lfs install
   git remote add origin https://github.com/sctell57/santa-game.git
   git fetch origin
   git checkout -t origin/main     # or the week-1 branch until it is merged
   ```
   If git refuses because of an untracked file with the same name (usually `.gitignore`), delete that file and run the checkout again.
3. Open the project in Unity. In the menu bar, run in order:
   - **Evil Santa > 1. Install Week 1 Packages** (Input System, Cinemachine 3, Netcode for GameObjects, Multiplayer Play Mode). If Unity asks to enable the new Input System and restart, click **Yes**.
   - **Evil Santa > 2. Build Graybox Level**. This also applies the style guide render settings.
4. Open `Assets/_Game/Scenes/Level_Village_Graybox` and press Play.
5. Commit the Unity-generated folders once: `git add -A && git commit -m "Add Unity project settings"` (adds `ProjectSettings/`, `Packages/`, and every `.meta` file; always commit `.meta` files with their assets).

Menu items 2 and 3 only appear after the packages are installed. That's on purpose: the game scripts only compile once Input System, Cinemachine 3 and URP are present, so a fresh project never opens full of errors.

## Controls

| Action | Gamepad | Keyboard and mouse |
|---|---|---|
| Move | Left stick | WASD / arrows |
| Look | Right stick | Mouse (click to capture, Esc to free) |
| Sprint | LT | Left Shift |
| Jump | A / Cross | Space |
| Grab (hold) | RT | Left mouse or E |
| Throw while holding | RB or X / Square | Right mouse or F |
| Respawn | D-pad down | R |
| Hide controls | View / Select | Tab |

Hold grab and walk into a present to scoop it up. Let go to drop it. Throw goes where the camera points.

## What's in Week 1

```
Assets/_Game/
  Scripts/
    Player/    ElfInput, ElfMotor, ElfGrabber, ElfCameraRig, ElfTuning
    Gameplay/  Grabbable, SurfaceProperties (ice)
    UI/        ControlsHint (playtest overlay, throwaway)
    Editor/    GrayboxBuilder, StyleGuideRenderSettings
    Setup/     PackageInstaller (works before packages exist)
  (generated by the builder) Art/Materials, Prefabs, Scenes, Settings
Assets/ThirdParty/   bought packs go here, never in _Game
```

- **Elf**: Rigidbody capsule, 1.1 m tall like the style guide. Camera-relative movement, sprint, jump with coyote time and input buffering, short hops when you let go of jump, heavier falls, slides on ice.
- **Grab and throw**: presents hang on a soft spring so they wobble and swing; heavy ones slow you down and lag behind; throws spin.
- **Camera**: Cinemachine 3 Third Person Follow with wall avoidance, on a pivot that's separate from the elf (so the Week 3 ragdoll can't spin it).
- **Graybox village**: 90 m snowfield with a fence, 3 cabins with climbable roofs and glowing windows, the sleigh (with an empty drop-off trigger for Week 4), a platform with a ramp, two jump ramps, three ice patches, pines and 10 presents in three sizes. Fall off and you respawn.
- **Look**: palette colors, lighting, fog and Global Volume values from the Art Style Guide. The render settings tool sets the PC URP asset to the guide's values and the Mobile one to a lighter "Switch-sized" preset (0.75 render scale, MSAA 2x, 1024 shadows, no SSAO). Switch quality levels in Edit > Project Settings > Quality to compare.

## Tuning the feel

Select `Assets/_Game/Settings/ElfTuning` while playing and change numbers live. Because it's an asset, **Play Mode changes are kept** when you stop. Good first knobs: `walkSpeed`, `groundAcceleration`, `jumpHeight`, `fallGravityMultiplier`, `holdSpring` and `holdDamping` (lower damping = more wobble), `throwSpeed`.

## Ready for Week 2

Gameplay reads an `ElfCommand` struct instead of devices, grabbing goes through one `TryGrab` method (it becomes a host-confirmed request), and the camera binds at runtime, so networked elves can reuse these scripts.
